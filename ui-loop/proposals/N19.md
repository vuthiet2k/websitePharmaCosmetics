# Đề xuất — N19 (cần chủ dự án quyết — R5 / R7 / G.6)

**Việc:** N19 — WebKit iPhone 13: chữ drawer ☰ và thanh đáy vẽ mảnh như Montserrat 300, Chromium vẽ đậm 600.

## Nguyên nhân (đo 30/10/2026, vòng 36 — `ui-loop/checks/N19.mjs`, `ui-loop/evidence/N19/probe*.mjs`)

- Không phải lỗi riêng drawer / thanh đáy: **mọi chữ Montserrat toàn site** ở WebKit (Playwright, Windows) đều vẽ cùng một
  nét mảnh, bất kể `font-weight`.
- `layouts/theme.bwt:55` nạp `fonts.googleapis.com/css2?family=Montserrat:wght@300;400;500;600;700;800`. Google trả **1 file
  variable (trục `wght`)** dùng chung cho cả 6 độ đậm (30 khối `@font-face`, 5 file — mỗi file 1 subset, cùng file cho mọi
  độ đậm) — giống nhau với UA Chromium và UA iPhone.
- WebKit Playwright Windows **tính bề rộng theo độ đậm** (bề rộng chuỗi 15px: 300 = 245,22 · 600 = 253,63 · 800 = 260,89px,
  y hệt Chromium) **nhưng không vẽ trục `wght`** — nét chữ luôn là bản mặc định của file variable (mảnh nhất):

| "Lượng mực" chuỗi mẫu 15px (tổng độ tối điểm ảnh) | 300 | 400 | 600 | 800 |
|---|---|---|---|---|
| WebKit — Montserrat site (variable) | 1 075 | 1 076 | 1 091 | 1 104 |
| WebKit — file **tĩnh** từng độ đậm (`css2?family=Montserrat:wght@<w>`) | 2 674 | 3 503 | 5 601 | 7 759 |
| Chromium 390 — Montserrat site (variable) | 266 | 372 | 642 | 904 |
| Chromium 390 — file tĩnh | 280 | 373 | 611 | 842 |

  (WebKit iPhone 13 chụp ở DPR 3 nên số lớn hơn Chromium DPR 1; so trong cùng hàng.) Font hệ thống Arial 400/700 ở WebKit
  4 142 / 5 825 ⇒ WebKit vẽ đậm bình thường với font tĩnh. Ảnh: `ui-loop/evidence/N19/probe-static-webkit-iphone13.png`.
- `-webkit-font-smoothing` (antialiased / auto) không ảnh hưởng (đo 2 chế độ, số như nhau).
- **Chưa kiểm được Safari iOS thật** (máy dev không có) — Safari iOS ≥ 11 có hỗ trợ font variable, nên rất có thể đây chỉ là
  giới hạn của bản WebKit chạy kiểm trên Windows; agent KHÔNG khẳng định điều này.

## Vì sao agent không tự sửa

Cách sửa phía theme duy nhất làm WebKit kiểm vẽ đúng độ đậm là bỏ file variable: tự lưu Montserrat **tĩnh** 400/500/600/700
(woff2, subset latin + latin-ext + vietnamese) vào `assets/` và khai báo `@font-face` — chạm `ui-src/css/tokens.css` (KHOÁ,
R5), đổi cách nạp font (R7 / G.6 "thêm font"), và trùng phạm vi L03 ("rút font còn 400/500/600/700").

## Phương án — chủ dự án chọn

1. **Đóng N19, ghi nhận giới hạn công cụ kiểm:** giữ Google Fonts; ghi vào Phần E/G rằng ảnh WebKit (Playwright Windows) không
   dùng để đánh giá độ đậm chữ. Khuyến nghị nếu có thể kiểm 1 lần trên iPhone thật xác nhận chữ đậm đúng.
2. **Tự host font tĩnh (gộp vào L03):** 4 độ đậm × 3 subset ≈ 12 file woff2 trong `assets/`, `@font-face` trong
   `ui-src/css/tokens.css` (`font-display: swap`), preload 1 file 400 latin; gỡ `<link>` Google Fonts ở `layouts/theme.bwt`.
   Lợi: bỏ 2 kết nối bên ngoài (giúp L03), bỏ 300/800 đúng D.3. Rủi ro: dung lượng font tăng so với 1 file variable/subset;
   cần cập nhật luật R7 / B.1 cho phép.
3. **Giữ Google Fonts nhưng xin file tĩnh:** không làm được bằng 1 URL — Google luôn trả variable khi yêu cầu nhiều độ đậm.
